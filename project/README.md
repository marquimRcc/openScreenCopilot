# Registro do projeto

Esta pasta distingue **arquitetura proposta** de **código implementado**. Nada descrito
como futuro deve ser tratado como funcionalidade pronta.

Ordem de leitura: [situação](STATUS.md), [requisitos](REQUIREMENTS.md),
[arquitetura](ARCHITECTURE.md), [contratos](CONTRACTS.md), [decisões](DECISIONS.md),
[Windows 11](WINDOWS11.md), [testes](TESTING.md) e [plano](ROADMAP.md).

A política de isolamento das automações está em [CI-POLICY.md](CI-POLICY.md).

A direção de interface pós-gravação está em [SIMPLE-RECORDING-UX.md](SIMPLE-RECORDING-UX.md):
resultado simples primeiro, edição secundária; distinguir proposta de implementação.

A procedência, as licenças, o procedimento de atualização e a diferença entre
fork GitHub e importação com histórico estão em [UPSTREAMS.md](UPSTREAMS.md).

Cada etapa deve terminar com evidência verificável: commit/PR, comandos executados,
resultados e limitações em [STATUS.md](STATUS.md). Não marcar uma etapa como concluída
somente porque sua documentação foi escrita.
